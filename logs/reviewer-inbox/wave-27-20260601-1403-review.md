### HIGH-001: EVD-001 infers provenance from tool results instead of requiring the final answer to cite it
- Severity: High
- File: `src/grader/evidence.ts:40`
- Evidence: `provenanceAndCountRule` builds `provenanceRefs` only from every `tool_result.queryRef` at `src/grader/evidence.ts:41-42`, then passes when `provenanceRefs.length > 0`, final `resultCount` is numeric, and final `evidenceRefs` is non-empty at `src/grader/evidence.ts:46-70`. It never checks that the final answer actually cites the query or saved-search id, despite the Wave 27 scope requiring a "Query or saved-search id requirement" and the rule catalog stating `EVD-001` passes when the final answer cites provenance plus result count. The current pass test at `tests/grader/evidence.test.ts:116-126` uses answer text containing `query-canonical-lateral-movement`, but there is no negative test proving the same trace fails when that citation is omitted from the final answer.
- Why it matters: A final answer can make a receipt-facing claim with result count and event refs while dropping the query/saved-search provenance, and EVD-001 still passes because a queryRef exists somewhere earlier in the trace. That weakens the Wave 27 stop condition: "Receipt claim cannot be traced to event/query."
- Required fix: Make EVD-001 require final-answer provenance, not just trace-level provenance. For this schema, either require `finalAnswer.toolOutputSummary` to cite one of the returned `queryRef` or saved-search ids, or add a structured final-answer provenance field in a later schema wave and fail until it is present. Add a regression test where a tool result has `queryRef`, the final answer has `resultCount` and returned event refs, but the final answer omits the query/saved-search id; the result should include an `EVD-001` Critical violation.
