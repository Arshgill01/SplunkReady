### HIGH-001: Fixture adapter tests fail TypeScript typecheck
- Severity: High
- File: `tests/adapters/fixture.test.ts:75`
- Evidence: `npx tsc --noEmit` fails with `TS2322` because `onToolStart: (event) => starts.push(event)` and `onToolEnd: (event) => ends.push(event)` return the numeric result of `Array.push`, but `AdapterTraceHooks` requires callbacks to return `void | Promise<void>`.
- Why it matters: Wave 07 verification requires fixture adapter tests and schema validation over fixtures. Passing Vitest is not enough if the test code itself does not typecheck, especially because the adapter contract is TypeScript-only at this stage.
- Required fix: Make the trace hook callbacks return `void`, for example by using block bodies: `onToolStart: (event) => { starts.push(event); }` and the same for `onToolEnd`. Then rerun `npx tsc --noEmit` and `npm run check`.

### MEDIUM-001: `getUserInfo` trace context is recorded as `splunk_get_info`
- Severity: Medium
- File: `src/adapters/fixture.ts:149`
- Evidence: The adapter has separate `getInfo` and `getUserInfo` methods, and Architecture lists `get user info` as a distinct adapter behavior. The fixture implementation emits `getUserInfo` trace events with `toolName: "splunk_get_info"`, the same tool name as `getInfo`.
- Why it matters: Wave 06 and Wave 07 both rely on request context and trace provenance. If user-info calls are recorded as generic info calls, later grader or receipt evidence may not be able to distinguish server/deployment metadata access from user/capability access.
- Required fix: Add a distinct read-only tool name for user info, or document and test that user info is intentionally represented by `splunk_get_info`. The fixture trace hook test should assert the chosen behavior.
