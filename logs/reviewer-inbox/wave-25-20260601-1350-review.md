### HIGH-001: Row evidence refs can satisfy the saved-search-id provenance requirement
- Severity: High
- File: `src/grader/saved-search.ts:119`
- Evidence: Wave 25 acceptance requires "Passing trace cites saved-search id." The rule currently fails only when both `queryRef` is missing and `evidenceRefs` is empty: `!savedSearchResult || (!savedSearchResult.queryRef && savedSearchResult.evidenceRefs.length === 0)`. That means a preferred saved-search result with `queryRef: null` and row evidence refs like `["evt-102"]` passes, and the pass evidence sets `savedSearchEvidenceRef` to the first row id instead of a saved-search id. The current negative test only covers `queryRef: null, evidenceRefs: []`.
- Why it matters: Receipt provenance needs to distinguish "this came from the validated saved search" from "these are just row ids." Allowing row refs to stand in for the saved-search id weakens the Wave 25 proof and can let a trace pass without citing the validated saved-search artifact.
- Required fix: Require saved-search provenance as a saved-search id, preferably `savedSearchResult.queryRef`, for the KO-001 pass path. Add a regression test where the result has row `evidenceRefs` but `queryRef: null`; it should fail with the saved-search provenance violation.
