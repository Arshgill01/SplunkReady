## Findings

### MEDIUM-001: Receipt refs are unlabeled and cramped in the browser snapshot
- Severity: Medium
- File: `src/ui/shell.ts`
- Evidence: The Playwright snapshot for the generated shell shows the `Receipt refs` region rendering three adjacent lists without labels for trace refs, evidence refs, and violation refs. At a 1280px viewport the right-hand column is narrow, so long trace ids wrap into many short lines and the `No violation refs.` empty state appears as an unlabeled standalone box.
- Why it matters: Wave 34 requires the UI to emphasize receipt/provenance with clear, restrained operational text. The current top-level shell is operational, but the main provenance section makes the receipt refs harder to scan and weakens the evidence-first story.
- Required fix: Add compact labels for the three receipt-ref groups and give long identifiers more horizontal room, for example by stacking the groups at this breakpoint or using a two-column layout where trace refs get the wider track.
