## Findings

### HIGH-001: Rule evaluation status is not schema-validated
- Severity: High
- File: `src/grader/engine.ts:117`
- Evidence: `assertRuleBoundary` checks `result.ruleId` and `result.severity`, but it never validates that `result.status` is one of the structured statuses. The only branch is `if (result.status === "fail")`; any other status value with matching `ruleId` and `severity` reaches `return result` and is treated as non-failing by `results.flatMap((result) => (result.status === "fail" ? result.violations : []))`. The Wave 22 stop condition is "Rule engine accepts arbitrary prose as grade."
- Why it matters: TypeScript narrows local code, but the runtime engine boundary is where deterministic grading should reject malformed rule output. A rule returning `{ status: "looks safe", ruleId: "SPL-001", severity: "Critical" }` through a cast or plugin boundary would be preserved as a result and would emit no violation, effectively accepting arbitrary grade prose.
- Required fix: Add runtime validation for the complete `RuleEvaluation` union before returning it from `assertRuleBoundary`: allowed statuses only, pass results must include structured evidence and no violations, fail results must include structured violations, and malformed statuses must throw. Add a negative test that a non-`pass`/`fail` status is rejected.
