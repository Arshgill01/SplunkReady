## Findings

### MEDIUM-001: Reserved SPL keys are only ignored in lowercase
- Severity: Medium
- File: `src/grader/contract.ts:38`
- Evidence: `extractFieldCandidates` filters candidates with `!ignoredFieldTokens.has(field)`, but `ignoredFieldTokens` contains only lowercase `earliest`, `index`, `latest`, and `sourcetype`. The assignment regex is case-insensitive, so `SOURCETYPE=XmlWinEventLog:Security` is recognized as a sourcetype assignment, but the field-candidate regex can still capture `SOURCETYPE` and the lowercase-only ignore set will not remove it. The same applies to `INDEX`, `EARLIEST`, and `LATEST`.
- Why it matters: Splunk search syntax commonly treats these search modifiers as keywords, and agents may emit uppercase or mixed-case SPL. The contract rule can therefore add an unrelated `SPL-003` unknown-field violation to an otherwise valid query, which is exactly the kind of deterministic false positive the Wave 24 reviewer checklist asks us to control.
- Required fix: Normalize reserved-token checks with `field.toLowerCase()` before consulting `ignoredFieldTokens`, and add a regression test for uppercase or mixed-case `INDEX`, `SOURCETYPE`, `EARLIEST`, and `LATEST` that still evaluates only the actual user fields.
